# 川大导师速查

四川大学计算机学院（软件学院）导师信息检索站。数据来自学院官网，支持按研究方向筛选、查看职称与联系方式、一键跳转官方主页，内置一个基于本库资料的问答助手。

**在线访问：** https://qiuizi.github.io/scu-tutor-finder/

> 线上是纯静态版本，问答助手运行在「本地检索」模式（直接匹配库内数据，无需 API Key）。
> 想要自然语言对话，按下面「配置问答助手」在本地跑完整版。

## 它解决什么问题

学院官网的导师信息分散在三个地方，且字段填写率参差不齐：

| 数据源 | 提供什么 | 实测情况 |
|---|---|---|
| `faculty.scu.edu.cn` 教师主页系统 | 姓名、职称、邮箱、办公地点、个人简介 | 学院列表 **166 人**；全校仅 188 个主页 |
| 《研究生导师名录》PDF | **研究方向**（最权威） | 88 页，解析出 **81 位导师，方向 100% 齐备** |
| `ai.scu.edu.cn` | 学院通知、新闻、科研成果 | 26 条动态 |

本工具把三者合并成一个可检索的库：**188 位教师**，其中 99 位可查研究方向、82 位可确认研究生导师身份、177 位有公开邮箱。

## 目录结构

```
Tutor/
├── crawler/              # 数据抓取（Node，无额外框架）
│   ├── 01-roster.mjs     # 学院教师名单（21 页分页）
│   ├── 02-detail.mjs     # 个人主页字段 + 邮箱解密
│   ├── 03-pdf.mjs        # 导师名录 PDF 解析（按坐标还原表格）
│   ├── 04-merge.mjs      # 多源合并
│   ├── 05-allfaculty.mjs # 全校主页枚举（备用，定位漏收导师）
│   ├── 06-notices.mjs    # 学院通知
│   └── update.mjs        # 一键更新流水线
├── data/                 # 原始数据（JSON）
├── web/                  # Next.js 16 + Tailwind v4
│   ├── app/page.tsx      # 主页面
│   ├── app/api/agent/    # 问答接口（密钥只在服务端；静态部署时自动移除）
│   ├── components/       # 检索、详情抽屉、通知、助手面板
│   └── public/data/      # 前端直接加载的数据（构建时也从此读取）
└── .cache/               # 抓取缓存（可删，删后重抓）
```

## 怎么跑

```bash
# 1. 装依赖
npm install
cd web && npm install && cd ..

# 2. 抓数据（首次约 3 分钟；有缓存时很快）
npm run update

# 3. 启动
cd web && npm run dev     # 开发
# 或
npm run build && npm start   # 生产
```

打开 http://localhost:3000

## 配置问答助手

助手需要一个大模型。**密钥只放在服务端，不会暴露到浏览器。**

```bash
cd web
cp .env.local.example .env.local
# 编辑 .env.local，填入自己的 key
```

支持任何 OpenAI 兼容接口：

```ini
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=sk-...
```

没配 key 时，检索和详情功能完全可用，只有右下角的助手会提示未配置。

## 更新数据

```bash
npm run update          # 全量重抓（名单 → 详情 → PDF → 合并 → 通知）
npm run update:quick    # 只重新合并 + 抓通知（走缓存，几十秒）
```

数据更新后统计信息会自动写入 `web/public/data/meta.json`，页头会显示最新日期。

数据一提交，GitHub Actions 会自动重新构建并发布线上站点。

## 部署（GitHub Pages）

线上是纯静态导出，没有后端。两种模式的区别：

| | 线上（静态） | 本地（完整版） |
|---|---|---|
| 检索 / 筛选 / 详情 | ✅ | ✅ |
| 问答助手 | 本地检索（匹配库内数据） | 可接大模型做自然语言问答 |
| 需要 API Key | 不需要 | 需要 |

本地验证静态产物：

```bash
STATIC_EXPORT=1 node scripts/build-static.mjs   # 产物在 web/out
node scripts/preview-static.mjs 4000            # 起本地静态服务
```

推送 `main` 分支后，`.github/workflows/deploy.yml` 会自动构建并发布到 Pages。
首次部署需在仓库 Settings → Pages → Source 选择 **GitHub Actions**。

## 已知限制（重要）

1. **研究方向覆盖率 52.7%**。不是抓取失败——学院主页上很多教师（尤其讲师、退休教师）根本没填这一栏，字段本身就是空的。好消息是**研究生导师的覆盖是完整的**（81/81）。
2. **计算机学院主站 `cs.scu.edu.cn` 有瑞数 WAF**（`$_ts` 动态防护），静态请求拿不到 HTML。因此通知目前只收录人工智能学院。如需补全，得用无头浏览器。
3. **22 位资深导师没有个人主页**（如陈兴蜀、唐华锦、周激流）。学校只给他们上了名录 PDF，所以信息取自 PDF，页面会标注「无个人主页」。
4. **PDF 的邮箱列存在错位**（学校文件本身的问题，如把别人的邮箱排在某院士那行）。因此邮箱一律以个人主页解密结果为准，PDF 邮箱仅作兜底。
5. 邮箱通过站点自带的 `tsitesencrypt.jsp` 接口解密，并非破解；这本来就是这个页面给浏览器用的接口。

## 技术选型说明

- **不用数据库**：188 条记录、189 KB，前端直接全量加载，筛选零延迟。上 SQLite 属于过度设计。
- **不用向量库**：检索用「姓名 > 方向标签 > 简介」的分层关键词打分，可解释、零依赖，188 人规模足够准。
- **不用 shadcn CLI**：视觉遵循 shadcn/Tailwind 的设计语言（深色、细边框、靛蓝点缀），但组件手写，不引入 radix 依赖，降低构建失败面。
- **不用 Google Fonts**：国内构建常失败，改用系统字体栈（PingFang / 微软雅黑）。
